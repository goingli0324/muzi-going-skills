# 模型逐字稿校對（Step 6.5）

適用對象：Step 6 用 faster-whisper 補出來的 `_逐字稿.md`。平台字幕不走這步——那是人打的，錯字型態不同，也不該被機器改掉。

## 為什麼要分「機械正規化」與「人讀校對」兩段

Whisper 的錯有兩種。一種是規則能解的：簡體字、半形標點、`s2twp` 把「權限」轉成「許可權」這類過度轉換——交給 `scripts/clean_transcript.py prep`。另一種是要懂課程內容才抓得到的：專有名詞辨成同音字（「八包」＝ Bubble）、英文術語拼錯（Unboarding）、章／張互換、產品名三種拼法——這要一個讀過上下文的校對員，一份檔案一個 agent，平行跑。

## 流程

```bash
# 1. 每份檔案先 prep
python3 <skill>/scripts/clean_transcript.py prep "<章資料夾>/1-2 xxx_逐字稿.md" --workdir <工作目錄>/ch1

# 2. 每份 prep.txt 開一個 general-purpose agent（prompt 見下），平行跑；agent 寫 <n>.校對.txt

# 3. 每份 final：驗行數、加來源行、依 mp4 檔名落地成 <單元>.逐字稿.txt
python3 <skill>/scripts/clean_transcript.py final <工作目錄>/ch1/1-2.校對.txt --chapter "<章資料夾>"
```

`final` 在行數不一致時會直接擋下——那代表校對員併行或漏行，回去看 diff，不要放行。

## 校對 agent 的 prompt 模板

把 `<…>` 填好後整段給 agent。四份同時跑一輪約 2–4 分鐘。

```
你是繁體中文（台灣用語）逐字稿校對員。檔案：<prep.txt 絕對路徑>

背景：這是線上課程「<課程名>」第 <N> 章「<章名>」的單元「<單元名>」，由本機語音辨識（faster-whisper）產生，
講者是台灣講師，主題是 <一句話講這單元在講什麼、會出現哪些工具與術語>。
同一系列的常見辨識錯誤：<從下方字表挑相關的貼進來>。

任務：
1. 用 Read 讀整個檔案（第一行是單元標題，之後每行一句）。
2. 只修正「辨識錯誤」：同音錯字、英文術語拼寫、殘留簡體字、明顯斷錯的詞。不要改寫口語、不要刪贅詞、
   不要合併或拆分行、不要加內容。標點只動半形逗號／問號改全形，其他照舊。
3. 把校對後全文用 Write 寫到同資料夾的 <n>.校對.txt（第一行仍是標題，格式與原檔完全相同）。
4. 回報時只列：修改總行數、前 10 筆最重要的修正（「原 → 改」，每筆不超過 15 字）、以及你不確定的地方
   （最多 5 筆，寫行號）。不要在回報裡貼大段原文。
```

回報裡的「不確定的地方」要原封不動轉給使用者，並標明**沒有硬改**——那是要對照音檔才能定的，猜錯比不改更糟。

## 拿不準的字：切片重聽定案

使用者說「幫我聽一下」時不必真的聽，做等價的事：

```bash
python3 <skill>/scripts/relisten.py "<單元>.mp4" --at 02:58 03:08 05:39 --chars 導登
```

時間點取自 `_逐字稿_timestamps.md`。腳本切出該句前後各 1.5 秒，用 faster-whisper large-v3（無提示／中性提示）與 mlx whisper-large-v3-turbo 三種設定重跑，列出候選字的逐字信心值。**三種設定同一個字、信心值多在 0.9 以上才算定案**；分歧就照實回報請使用者聽。

實際踩過的坑：校對員依上下文（講者前面提到 Onboarding）把一份逐字稿裡九處「登入流程」推成「導入流程」，重聽三種設定全是「登」，一處都沒有「導」。上下文推論只能拿來標「不確定」，不能拿來改字。

### 重聽結果怎麼判（跑過三十多個片段後歸納的）

先問一件事：**兩個候選字在音檔上分不分得出來？** 這決定該信模型還是信語意。

| 情況 | 怎麼判 | 例子 |
|---|---|---|
| 候選字不同音，三種設定同一個字 | 照模型改，校對稿與它不同就還原 | 登入≠導入、陌生人≠陌生網站、什麼≠怎麼、注意≠作業 |
| 候選字不同音，三種設定分歧 | 不改，回報三種各聽到什麼 | Python／排程、Web Service／Web SaaS、紳士／深色 |
| 候選字是真同音字 | 音檔永遠定不了，只能靠語意，改了要標明是語意判斷 | 張／章、在／再、的／得 |
| 英文專有名詞，三種都是近似音但拼法各異 | 拼成語意上唯一合理的詞，標明是語意判斷 | MaskHalf／MathHub／Must-Half → Must Have（功能清單） |
| 三種一致，但那個字在句子裡講不通 | 保留語意合理的版本，標不確定 | 「醜這樣子的模式」三種都是醜，語意是「抄」 |
| 產品名、公司名 | 音檔定不了拼法，保留原始辨識或校對員版本，列給使用者 | 同一個產品名被聽成三種拼法、一家聽不出來的金流公司 |
| 原始辨識整句被前一段蓋掉 | 三種都聽到不同的一句時，用聽到的那句取代，並看前後行是否要一起調 | 「最後呢是系統流程圖」實為「最後呢是系統的回饋狀況」 |

「三種設定」指 faster-whisper large-v3 無提示、同模型中性提示、mlx whisper-large-v3-turbo。信心值只是輔助：同一個字三次都 0.9 以上很篤定，但 0.5 上下三次一致也算一致；真正的訊號是**三個獨立設定有沒有指向同一個字**。

回報固定分三類：已改（附依據）、跑過確認校對稿沒問題、仍不確定（附三種各聽到什麼）。第三類要給時間點，使用者才能自己去聽。
